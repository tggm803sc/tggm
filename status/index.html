What gates a merge into main, right now. Required checks are pinned to the GitHub Actions app so another app cannot report a green check in their name.

Both CI repos gate pull requests into main with the owner included: nothing merges on a red run, and neither repo allows a force-push or a branch delete on main. Direct pushes to main are a separate story — classic branch protection does not gate them, and no ruleset covers them yet.

03

Verification ledger

Two columns, and the second one matters more. A green check proves a command exited zero — not that a person played the game or opened the app.

Verified, with evidence

  • Required checks are armed on main in tgg-studio and tru-go-getta-mixtape, both pinned to app 15368 (GitHub Actions).
  • The owner is not exempt. Protection reads back as enforcement_level: everyone with enforce_admins: true.
  • Green push-triggered runs on main were observed before the checks were required: 20s and 13s, zero annotations on both.
  • The workflow files match. Local files hash to the same blobs GitHub stores on main (87816c43, b9777b53).
  • The merges happened in the planned order — CI workflow first, runner image second — so no pull request sat waiting on a check that did not exist yet.

Not verified — say so

  • That a red run actually blocks a merge. No failing run was pushed to prove the refusal.
  • Direct pushes to main. Protection covers pull requests; a direct write is still open.
  • Any browser rendering. The build environment has no browser and no device, so no TGG app was looked at in a viewport.
  • Step-level CI logs. Run summaries were read; individual job steps were not.
  • Deployments, databases and provider calls. No credentials for any of them were available.
  • The private universe suites and the Unreal tree. Five .mjs suites sit in an unclonable private repo, and the Unreal folder has no project file or engine to compile against.
04

Open blockers

Kept out loud, because a blocker nobody wrote down becomes a surprise.

  1. B7

    CI gap across the suite

    The two repos with real app code now gate main. Closed after both workflows merged and the required checks were armed.

    Closed
  2. B9

    The suite is not uniformly instrumented

    tggm still has no push-gated CI, and tgg-os runs its checks without requiring them.

    Partly open
  3. B11

    No GitHub credentials in the build environment

    Every write goes through the API instead of a clone-and-push, which makes large file edits impractical.

    Open
  4. B12

    The OCI host is not reachable

    Ingress on 8787 is closed and the deploy is waiting on external execution, which holds the related TGG pull requests behind a live host.

    Open
  5. B13

    No provider keys

    Generation and model providers have no keys here, and no database URL is configured — so nothing depending on them can be exercised.

    Open

The rule the whole board runs on

Nothing here gets to claim a test that nobody ran.

TGG keeps its receipts: links to the runs, hashes of the files, and a plain list of what is still unproven. When something moves from the right column to the left, the evidence moves with it.
